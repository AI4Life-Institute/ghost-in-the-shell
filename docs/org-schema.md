# Org schema (normative)

This is the **single authority** for the `Org/<org>/` file format that ghost
reads, writes, and enforces. Ghost's resolver, owner-resolution, dispatch
guard, lint, and `ghost butler onboard` all conform to it. The companion
conformance harness is the vault POC
`Projects/Ghost/tasks/discord-bot/2026-05/2026-05-31-or6t4n-org-schema-poc.py`
— the lint / resolver / owner / guard here must reproduce its behavior exactly.

> **Responsibility split.** The **vault owns the data + semantics** (the
> `*.yaml` files, the `reports_to` structure, scope assignment, descriptions —
> edited by PM/human directly). **Ghost owns the code** that reads/writes/
> enforces. Ghost's *only* write path is `onboard`, and it only ever **creates
> one new node file** (plus regenerating the derived `tree_snapshot`). Ghost
> NEVER batch-edits or hand-rewrites an existing node's `scope`/`reports_to`.

---

## Locating the org directory

Ghost is installed globally and may run from anywhere, so every org operation
first resolves WHICH vault and WHICH org (`gits/butler/org.py`):

1. **Vault root** = `git rev-parse --show-toplevel` from the caller's cwd (the
   same resolution butler send/dispatch use). The org dir is
   `<vault-root>/Org/`. Not in a git worktree → halt.
2. **Org (subdir)**: `--org <slug>` if given; else if exactly one `Org/*/` has a
   `_meta.yaml`, use it; else resolve by the caller's own node — read
   `<vault-root>/.butler.json` `channel_id`, find the org whose node files
   contain it. Still ambiguous → halt asking for `--org`.
3. **Per-worktree copies are expected.** Each worktree has its own `Org/` copy;
   ghost only ever touches `<caller-vault-root>/Org/`. `onboard` writes + commits
   in the caller's worktree and converges to other worktrees through vault-sync.
   Ghost does NOT reach across worktrees and does NOT `push` on its own.

## Directory

```
Org/<org>/                one directory per org (slug). Org discovery =
                          subdirs of Org/ that contain a _meta.yaml.
  _meta.yaml              org-level config + rules (NOT a node).
  <alias>.yaml            one file per agent/node. Filename stem MUST == `alias`.
```

## `_meta.yaml` — required keys

| key | type | meaning |
|---|---|---|
| `org` | string | org slug; MUST == the directory name |
| `guild_id` | string | Discord guild this org lives in |
| `onboarding_category` | string | category id new channels are created under |
| `root` | string | alias of the federation root (the single node with `reports_to: null`) |
| `rules` | map | normative rules (`dispatch` / `onboarding` / `owner_resolution`) — human-readable; enforced by code |
| `tree_snapshot` | sequence | **DERIVED** render of the whole `reports_to` tree as a YAML sequence: leaf = alias (string), parent = `{alias: [children]}`, siblings sorted. A view cache, NOT a source of truth. Regenerated by `onboard`; lint compares it **structurally** (parsed equality). **MUST be the LAST top-level key** — `onboard` regenerates it by replacing from the `tree_snapshot:` line to EOF, leaving every hand-written comment above intact. Never hand-edit. |
| `legacy_category` | string | optional |

**Config authority.** `guild_id` + `onboarding_category` are authoritative here
in `_meta.yaml` (per org). The legacy global `~/.gits/butler-onboarding.json` is
**superseded** for any org that has a `_meta.yaml`; `onboard` reads `_meta.yaml`
first and only falls back to the global file if no org is resolved. The worktree
parent dir is a machine setting: `onboard` defaults it to `dirname(<vault-root>)`
(worktrees are siblings of the vault) and honors `GITS_WORKTREE_PARENT` as an
override.

## `<alias>.yaml` — node fields

| field | type | required | rule |
|---|---|---|---|
| `alias` | string | ✓ | unique within org; == filename stem; `^[a-z][a-z0-9_-]*$` (root may be CamelCase) |
| `channel_id` | string | ✓ (real nodes) | Discord channel snowflake; omitted only for the abstract root |
| `human` | string \| null | ✓ | real operator name; `null` = 职能/test channel. **NOT unique** across nodes |
| `reports_to` | string \| null | ✓ | parent alias; `null` ONLY for the single root; MUST resolve to a node in the same org |
| `scope` | list&lt;string&gt; | ✓ | vault-root-relative folder paths owned by default; may be empty |
| `desc` | string | ✓ | one line; may be `""` |
| `kind`, `chair` | string | root only | `kind: federation-root`, `chair: <operator>` |

`onboard` writes new node files via `yaml.safe_dump` with a one-line provenance
header comment; node files are never round-tripped (only created), so comment
preservation is not required for them — only for `_meta.yaml`.

## Invariants — lint enforces, HARD (fail = reject)

Implemented in `gits/butler/org.py:lint` (pure) + `lint_org_dir` (disk-level).
Errors name the offending `file:field` so a future editor fixes it in one read.

- every node has all required fields, correct types; **no unknown keys**.
- `alias` matches `^[a-z][a-z0-9_-]*$` (root may be CamelCase). **Explicit
  check** — not relied on incidentally via another rule.
- filename stem == `alias`.
- `alias` unique within the org (enforced by the filesystem + this check).
- `channel_id` unique across nodes — one Discord channel ↔ exactly one node.
- **exactly one** node with `reports_to: null`, and it == `_meta.root`.
- every non-null `reports_to` resolves to a node **in the same org** (no
  cross-org edges).
- the `reports_to` graph is **acyclic** (a tree, connected to root).
- **`scope` folders are mutually exclusive**: no two nodes declare the same
  folder path. Prefix-nesting IS allowed (a deeper folder under another node's
  folder = how reassignment works); an exact duplicate folder = ambiguous owner
  → reject.
- **`_meta.tree_snapshot` equals the reconstructed tree** (structural / parsed
  comparison, not string match). Catches a hand-edited `reports_to` that didn't
  regenerate the snapshot.
- **`tree_snapshot` is the last top-level key** in `_meta.yaml` (disk-level;
  keeps the onboard splice safe).
- (warn, not fail) each `scope` path exists on disk under the vault root.

## Semantics — enforced by ghost code, not by the file

> **Scope note (or6t4n / Phase 2).** `owner_resolution`, `is_descendant`, and
> `can_dispatch` ship here as **pure, tested** functions in `org.py`, but are
> **not yet wired into live dispatch** — routing/guarding the critical dispatch
> path is a separate follow-up task so this change stays additive. The
> definitions below are normative for that wiring.

- **dispatch**: a node may dispatch only to a **strict descendant** in the
  `reports_to` tree. No lateral / cross-subsidiary dispatch. Cross-team work
  escalates to the common ancestor. **Exemption**: the human **chair** (and any
  caller whose `home_channel` resolves to no node — e.g. operating from `main`)
  is treated as the root and may dispatch to anyone.
- **owner_resolution** for a task at path `P`:
  1. among all nodes' `scope` folders that are a path-prefix of `P`, take the
     **deepest** → that node is owner;
  2. none match → walk **up** parent folders of `P` and retry;
  3. still none → **root** = **UNASSIGNED**. The root is abstract (no
     `channel_id`), so dispatch MUST NOT auto-open a thread on it — surface the
     task to the chair for an explicit `owner:`/`--reports-to`.
  4. an explicit task `owner: <alias>` in frontmatter **overrides** all of the
     above. ("parent" here = parent **folder**, NOT the `reports_to` tree.)

## Enforcement — at the git boundary, not just at onboard time

The same lint runs (a) inside `onboard` (before write — see below), AND (b) as a
**commit-time gate** on any change touching `Org/**`, via `ghost org lint`.

`ghost org lint [--org <slug>]` is deterministic (same input → same verdict),
runs standalone, exits non-zero on any HARD error (warnings allowed).

**Ready-to-paste vault `.githooks/pre-commit` stanza** (the vault PM installs
this in the vault repo — it is intentionally NOT committed by ghost):

```bash
# --- org-tree gate (ghost org lint) ----------------------------------------
# Reject any commit that would land a broken Org/** tree (dup alias / dup
# channel_id / dangling reports_to / second root / cycle / overlapping scope /
# snapshot drift). Lints the WORKING TREE (matches the POC). If `ghost` is not
# on PATH we warn-and-pass so non-ghost committers aren't blocked.
if git diff --cached --name-only | grep -q '^Org/'; then
  if command -v ghost >/dev/null 2>&1; then
    if ! ghost org lint; then
      echo "❌ ghost org lint failed — fix the file:field error(s) above, or commit --no-verify to override." >&2
      exit 1
    fi
  else
    echo "⚠ ghost not on PATH — skipping org-tree lint (install ghost to enable the gate)." >&2
  fi
fi
```

## `ghost butler onboard` — lifecycle

`ghost butler onboard <name> [--org] [--reports-to] [--scope ...] [--human]
[--cli] [--desc] [--dry-run]`. Run from inside the PARENT's worktree (the
caller's node becomes `reports_to` by default). Implemented in
`gits/butler/onboard.py`. Ordered steps, each one concrete action:

1. Validate `<name>` (regex + reserved word `main`/`master`/`head`).
2. Resolve org + parent (`--reports-to` or caller's node). Assert parent exists.
   Running from `main` / an unregistered channel makes `--reports-to` required.
3. Guard: no existing `Org/<org>/<name>.yaml`; resume an existing
   `vault-<name>` worktree / local `<name>/work` branch; **refuse** if the
   branch already exists on origin.
4. Create the Discord channel under the org's `onboarding_category` (reuse a
   matching channel if present — re-onboard case).
5. **Atomic** node write: build the node, run the trial lint with it added
   **before writing**, write `Org/<org>/<name>.yaml`, surgically regenerate
   `_meta.tree_snapshot`, re-lint on disk, then `git add` + `git commit` the two
   files together. On any failure, `git checkout -- Org/` + remove the new node
   so the tree is exactly as before.
6. `git worktree add <wt-parent>/vault-<name> -b <name>/work` from caller HEAD.
   **No `push`** — vault-sync propagates the branch.
7. Bind the home channel, `ghost butler send "/bind <worktree> <cli>"`, await
   the 🔗 reaction (~5s).
8. Verify (`lint_org_dir` clean) and 9. print a summary.

**Idempotency.** Re-running for an existing name is a no-op-or-resume, never a
duplicate: node present + matching `reports_to` → "already onboarded"; node
present but different `reports_to` → refuse (no clobber); channel/worktree
present but node missing → finish the missing steps. On a halt after partial
side-effects, onboard reports exactly what was created so the operator can clean
up or resume.

**Relationship to the `onboard-worktree` skill.** The skill stays as the
human-facing trigger but **delegates** the mechanical + atomic parts (node-file
write + lint + commit) to this command. The skill must never hand-edit the
registry.

## Future lifecycle ops — NOT automated here, but kept lint-safe

These are MANUAL vault edits (human/PM) for now; the commit-time gate keeps them
honest:

- **offboard** (remove a node): delete the file — lint then fails if any child
  still has `reports_to: <removed>`, forcing a re-parent first.
- **re-parent / reorg**: edit `reports_to`; lint rejects cycles / dangling.
- **rename alias**: rename the file AND update every child's `reports_to` AND the
  channel binding — deliberately NOT automated (alias is meant to be stable). A
  future `ghost org mv` could own this.
